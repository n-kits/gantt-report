# Лента времени — веб-версия диаграммы Ганта

Веб-аналог листа «Лента времени» из отчёта `Диаграмма_Ганта_*.xlsx`, который строит
[`tools/gantt_report.py`](tools/gantt_report.py). Страница строит ту же почасовую ленту
(тот же расчёт, цвета и разметку) прямо в браузере и перестраивает её при загрузке
новой выгрузки.

## Запуск

Сборка не нужна — это статическая страница.

- **Локально:** открыть `index.html` двойным кликом или запустить сервер:
  ```bash
  python -m http.server 8765
  ```
  и открыть http://localhost:8765
- **GitHub Pages:** Settings → Pages → Deploy from branch → `main` / `(root)`.

Данные никуда не отправляются: файл читается в браузере. Последняя загруженная выгрузка
и настройки сохраняются в `localStorage` и переживают перезагрузку страницы.

## Использование

1. Нажмите «Загрузить файл» или перетащите выгрузку на страницу (`.xlsx`, `.xls`,
   `.csv`, `.html`).
2. Поле **«Сейчас»** — момент расчёта. Незавершённые задачи тянутся до него. По умолчанию
   берётся из имени файла (`..._2026_09_27_03_00_46.xlsx`), иначе текущее время.
3. **«Начало оси»** — час начала суток на оси (по умолчанию 4, как `--day-start` в скрипте).
4. **«Колонка»** — шаг ленты (1–6 ч), **«Колонок»** — «до 72» как в Excel-отчёте или «все».

## Формат входных данных

Колонки выгрузки (порядок всегда такой):

| # | Колонка       | # | Колонка      |
|---|---------------|---|--------------|
| 1 | Название      | 6 | Завершение   |
| 2 | Проект        | 7 | Статус       |
| 3 | Регистрация   | 8 | Крайний срок |
| 4 | Исполнитель   | 9 | Вид продукции|
| 5 | Виды работ    |   |              |

- Если в первых 10 строках есть строка заголовков — колонки определяются по названиям
  (лишние пробелы, регистр и нумерация вида `1.`/`2)` не мешают; синонимы — `COL_ALIASES`
  в [`js/model.js`](js/model.js)).
- Если заголовков нет — колонки берутся по порядку из таблицы выше; строки без
  распознаваемой даты регистрации пропускаются. На странице появится предупреждение.
- Даты: `14.09.26 07:59:00`, `14.09.2026 07:59`, `2026-09-14 07:59` или настоящие даты Excel.

## Устройство

```
index.html
css/styles.css          оформление (палитра из gantt_report.py)
js/model.js             расчёт: разбор строк → задачи → окно → ячейки ленты (порт Python-логики)
js/timeline.js          рендер таблицы и подсказки
js/app.js               UI: загрузка, настройки, localStorage
js/sources/             адаптеры источников данных
  xlsx-source.js        .xlsx/.xls/.csv через SheetJS
  html-source.js        HTML-страница списка задач Bitrix
vendor/xlsx.full.min.js SheetJS 0.20.3 (Apache-2.0), локальная копия — работает без интернета
tests/index.html        тесты модели (открыть в браузере)
tools/gantt_report.py   исходный Python-генератор Excel-отчёта
```

Каждый адаптер источника возвращает `{ rows, sourceName, kind }`, где `rows` — массив строк
таблицы (массив массивов). Модели всё равно, откуда пришли строки.

### Новый источник данных

```js
window.GanttSources.push({
  id: 'my-source',
  canRead(file) { return file.name.endsWith('.json'); },
  async read(file) { return { rows: [...], sourceName: file.name, kind: 'my-source' }; },
});
```

Для источников не из файла (API, букмарклет) есть `GanttApp.loadRows(rows, sourceName, now)`.

## Bitrix: задел на будущее

`js/sources/html-source.js` уже разбирает HTML грида Bitrix (`table.main-grid-table`,
ячейки `.main-grid-cell-content`, заголовки `.main-grid-head-title`) и выкидывает служебные
колонки (чекбоксы, меню действий). Сейчас так можно загрузить **сохранённую страницу**
списка задач (Ctrl+S → «Веб-страница, только HTML»).

Возможные следующие шаги:

1. **Букмарклет / расширение** на странице Bitrix: запускает `GanttHtml.parseHtml(document)`
   на живой странице и передаёт строки в эту страницу (`postMessage` или `localStorage`
   на общем домене) → `GanttApp.loadRows(...)`. Авторизация остаётся в браузере пользователя,
   CORS не мешает.
2. **Серверный парсер** (если нужно по расписанию): отдельный скрипт логинится в Bitrix,
   забирает страницу, прогоняет тот же разбор и складывает JSON рядом со страницей.

Важно: грид Bitrix показывает только видимые колонки и текущую страницу пагинации —
в настройках грида нужно включить все 9 колонок и поставить достаточный размер страницы.

## Тесты

Открыть `tests/index.html` (через локальный сервер или напрямую). Логика сверена с
Python-скриптом на реальной выгрузке: все 74 задачи × 72 колонки, цвета, отметки срока
и строка «Одновременно в работе» совпадают с листом «Лента времени».
