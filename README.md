# Лента времени — веб-версия диаграммы Ганта

Веб-аналог листа «Лента времени» из отчёта `Диаграмма_Ганта_*.xlsx`, который строит
[`tools/gantt_report.py`](tools/gantt_report.py). Страница строит ту же почасовую ленту
(тот же расчёт, цвета и разметку) прямо в браузере и перестраивает её при загрузке
новой выгрузки.

## Запуск

Сборка не нужна — это статическая страница.

- **Локально:** открыть `index.html` двойным кликом или запустить сервер:
  ```bash
  python -m http.server 8765
  ```
  и открыть http://localhost:8765
- **GitHub Pages:** Settings → Pages → Deploy from branch → `main` / `(root)`.

Данные никуда не отправляются: файл читается в браузере. Последняя загруженная выгрузка
и настройки сохраняются в `localStorage` и переживают перезагрузку страницы.

## Использование

1. Нажмите «Загрузить файл» или перетащите выгрузку на страницу (`.xlsx`, `.xls`,
   `.csv`, `.html`).
2. Незавершённые задачи тянутся до момента выгрузки — он берётся из имени файла
   (`..._2026_09_27_03_00_46.xlsx`), иначе используется время загрузки файла.
3. Ось всегда начинается с 04:00 дня первой задачи.
4. Колонка = 1 час, показывается до 72 часов с данными (как в Excel-отчёте); справа всегда
   запас из 6 пустых колонок под свежие задачи.
5. Текущий час (по часам компьютера) подсвечен оранжевым; подсветка переезжает сама.
6. Наведение на час подсвечивает всю колонку — удобно сверять с «Одновременно в работе».

### Замороженные функции

Код рабочий, но в интерфейсе скрыт — возвращается одним флагом.

| Функция | Как включить |
|---|---|
| Поля **«Колонка»** (шаг 1–6 ч) и **«Колонок»** (до 24 / 48 / 72 / все) | `FEATURES.viewControls = true` в [`js/app.js`](js/app.js). Проверить без правки кода: добавить `?controls=1` к адресу |

Разметка полей лежит в `<template id="view-controls-tpl">` в `index.html`. Пока функция
выключена, сохранённые в браузере шаг и лимит не применяются — всегда 1 ч и «до 72».

**Архивные виды точек на карте.** Основной вид — «половинки» (левая — задачи сегодня, правая —
вчера–позавчера, у каждой свой размер). Остальные рабочие и включаются параметром адреса:
`?points=core` («две точки в одной»: серый круг по всем задачам за три дня, зелёное ядро по сегодняшним),
`?points=pair` (пара кругов рядом), `?points=split` (два круга в одном месте), `?points=dot` (круг: цвет «сегодня» / «раньше»), `?points=pie` (сектора по дням), `?points=ring`
(дуги по дням). Сменить основной — `DEFAULT_POINT_STYLE` в [`js/map/geo-map.js`](js/map/geo-map.js).
Сравнение всех видов на реальных данных — `in/geo-compare.html`
(`python tools/collector/geo_review.py --compare-from in/live-real.json`).

## Формат входных данных

Выгрузка Bitrix **«Отображаемый список задач»**, 9 колонок строго в таком порядке,
заголовков нет (первая строка выгрузки — пустая «шапка» из пробелов):

| # | Колонка Bitrix       | Поле в модели / в gantt_report.py |
|---|----------------------|-----------------------------------|
| 1 | Название задачи      | `name` — Название                 |
| 2 | Статус               | `status` — Статус                 |
| 3 | Регистрация          | `start` — Регистрация             |
| 4 | Завершение           | `finish` — Завершение             |
| 5 | Текущий исполнитель  | `executor` — Исполнитель          |
| 6 | Крайний срок         | `deadline` — Крайний срок         |
| 7 | Проект заказчика     | `project` — Проект                |
| 8 | Вид продукции        | `product` — Вид продукции         |
| 9 | Выполнение задачи    | `works` — Виды работ              |

Порядок задаётся `FIELD_ORDER` в [`js/model.js`](js/model.js). Строки, где в 3-й колонке
нет даты регистрации (шапка, мусор), пропускаются.
- Даты: `14.09.26 07:59:00`, `14.09.2026 07:59`, `2026-09-14 07:59` или настоящие даты Excel.

  data.js               модель analytics.json, фильтры, окно 7 дней, графы связей

  html-source.js        сохранённая HTML-страница (Bitrix-список → bitrix-tasks.js)

Каждый адаптер источника возвращает `{ rows, sourceName, kind }`, где `rows` — массив строк
таблицы (массив массивов). Модели всё равно, откуда пришли строки.

### Новый источник данных

```js
window.GanttSources.push({
  id: 'my-source',
  canRead(file) { return file.name.endsWith('.json'); },
  async read(file) { return { rows: [...], sourceName: file.name, kind: 'my-source' }; },
});
```

Для источников не из файла (API, букмарклет) есть `GanttApp.loadRows(rows, sourceName, now)`.

## Живые данные из Bitrix

```
[ПК со сборщиком] Планировщик Windows, раз в полчаса (в :15 и :45)
  └─ tools/collector/collect.py: Playwright + Edge (свой профиль с входом в Bitrix)
       → «ВСЕ КАРТЫ Р24» за последние 3 суток по регистрации
       → js/sources/bitrix-tasks.js разбирает таблицу прямо в странице
       → шифрует (AES-GCM, ключ PBKDF2 из общего пароля) → push в ветку data (один коммит, без истории)
[Страница] читает raw.githubusercontent.com/…/data/live.json раз в 5 минут,
           расшифровывает паролем (вводится один раз) и перестраивает ленту
```

Данные в публичном репозитории только зашифрованные; открыто лежат лишь служебные поля
(время, статус сборщика, число задач).

### Установка сборщика (один раз, на ПК, который будет включён)

```bash
python -m pip install playwright cryptography anthropic geopy
python tools/collector/collect.py --setup         # пароль для коллег, интервал (по умолчанию 30 мин)
python tools/collector/collect.py --login         # окно Edge: войти в Bitrix, «Запомнить меня»
python tools/collector/collect.py --dry-run -v    # проверка без публикации
python tools/collector/collect.py -v              # первая публикация
python tools/collector/collect.py --install-task  # запуск по расписанию
```

Настройки, профиль Edge и журнал — в `%LOCALAPPDATA%\gantt-collector`
(`config.json`, `collector.log`). Интервал меняется в `config.json` → `interval_min` (минуты), привязка к минуте часа —
`align_minute` (15 → запуски в :15 и :45; `null` — от момента установки); затем повторить
`--install-task`.

Если сессия Bitrix истекла, сборщик публикует статус «нужен вход» (страница покажет
предупреждение и последние удачные данные) — достаточно снова выполнить `--login`.

### Карта топонимов (только живые данные)

Под лентой — карта мест из заказов за те же три дня. Сегодняшние (с 04:00) точки пульсируют,
вчерашние и позавчерашние — серые; размер точки растёт с числом задач, страны подсвечиваются
полигоном. Колесо мыши — масштаб, перетаскивание — сдвиг.

```
collect.py (тот же запуск)
  → колонка «Описание» в списке задач (превью, Bitrix обрезает до ~200 символов)
  → для новых/изменённых задач — полный текст со страницы задачи (#textDescriptionBlock)
  → tools/collector/geo.py: Claude (structured output) — тема, конфликт, тональность,
    топонимы с макрорегионом, кодом страны и оценкой координат
  → координаты: кэш (geocache.json) → Nominatim по запросу с макрорегионом → оценка модели
    (сверка: точка из кэша/Nominatim дальше допуска от оценки модели — отбрасывается)
  → раздел geo в зашифрованном live.json (без текстов описаний)
```

- Под картой — сводная таблица «Задачи и топонимы» (источник координат, расхождение с оценкой
  модели); клик по «Регистрации» меняет порядок сортировки.
- Цвета карты — переменные `--map-*` в `css/styles.css`.
- Точка — «половинки»: левая зелёная — задачи сегодня, правая серая — вчера–позавчера; радиус каждой —
  4 px + 1 px за каждую следующую задачу, не больше 40 (`radius` в `js/map/geo-model.js`). Подсказка
  «Москва 9 / 23» — задач сегодня / вчера–позавчера. Подобрать формулу и вид интерактивно —
  стенд `python tools/collector/geo_review.py --sizes` → `in/geo-sizes.html`; архивные виды — см. «Замороженные функции».
- Колонка «Описание» в Bitrix не обязательна (полный текст берётся со страницы задачи);
  если включена — ставить **последней** (выгрузка xlsx читается по позициям), тогда сборщик
  замечает правки описаний.
- **Анализ через Claude по умолчанию выключен** (`"llm": false`). «Стоп» для LLM — лента, карта по уже разобранным задачам и архив продолжают обновляться, к Claude
  ничего не уходит: двойной клик по `tools/collector/llm-off.cmd` (включить — `llm-on.cmd`, состояние —
  `llm-status.cmd`) или `python tools/collector/collect.py --llm off|on|status`. Действует со следующего
  запуска сборщика. Новые задачи тем временем ждут в очереди (их тексты скачиваются один раз и
  сохраняются) и разбираются после включения, если ещё в окне. Пока анализ выключен, карта и
  таблица «Задачи и топонимы» на сайте не показываются — только лента.
- Ключ: переменная окружения `ANTHROPIC_API_KEY`; модель (по умолчанию `claude-sonnet-5-5`) и
  глубина — `llm_model`, `llm_effort` в `config.json`; выключить карту — `"geo": false`.
- Регион в ответе LLM — свободная строка (`"llm_region_list": false`; `true` — закрытый список субъектов РФ
  и областей Украины), кэша промпта нет (`"llm_cache_ttl": null`; `"5m"` / `"1h"` — включить). Выбрано A/B-тестом
  на 80 архивных заказах (10.2026): качество одинаковое, без списка запрос вдвое дешевле; кэш окупается только
  при частых запросах подряд, а сборщик шлёт по одному заказу раз в 15+ минут.
- Дообработка архива (дни из `--backfill` — только строки ленты, без анализа):
  `python tools/collector/llm_archive.py fetch` (описания из Bitrix → очистка → архив), затем
  `python tools/collector/llm_archive.py apply --variant B` (пакеты по 8 с часовым кэшем, запись в архив и Excel).
  A/B-сравнение вариантов запроса — `llm_archive.py test` → `in/llm-test.html`.
- Страница проверки с реальными данными (локально, не публикуется): `python tools/collector/geo_review.py`
  → `in/geo-review.html`.
- Кэш координат заполняется один раз: `python tools/collector/collect.py --import-geocache <файл.geojson>`.
- Не найденные геокодером места (показаны по оценке модели, пунктирный ободок) — в
  `geo-unresolved.log`; поправить можно в `geocache.json` (`"Название (Регион)": [широта, долгота]`).
- Подложка `data/basemap.json` собирается из полигонов стран: `python tools/build_basemap.py <страны.geojson>`.
- **«Что это за место» — по координатам, а не по тексту LLM** (`tools/collector/places.py`). Регион и
  страна определяются попаданием точки в границы из `data/admin1.json.gz` (Natural Earth admin-1),
  поэтому формулировка одна для всех заказов. Спорные территории — одно правило: Крым, Севастополь,
  Донецкая, Луганская, Запорожская и Херсонская области — Россия. Одно место — один идентификатор (`pid`):
  населённый пункт — название + регион, территория или объект — название + страна, водный объект — название.
  Так «Казань / Татарстан» и «Казань / Республика Татарстан» сливаются, а Днепр-город и Днепр-река — нет.
  В анализе LLM регион выбирается из закрытого списка (субъекты РФ и области Украины) и служит только
  подсказкой геокодеру. Справочник пересобирается командой `python tools/build_admin1.py
  <ne_10m_admin_1_states_provinces.geojson> <cntpol10.geojson>`; при смене правил поднять `VERSION` в
  `places.py` — сборщик сам пересчитает архив (без LLM) и Excel.
- Одно название в разных местах одной страны (две деревни или ошибка) — раздел «Проверить» на странице
  проверки (`geo_review.py`) или `python tools/collector/places.py --check`.
- Тестовые данные с картой: `python tools/collector/make_geo_sample.py`, затем
  `index.html?data=tests/fixtures/live-geo-sample.json` (пароль `test`).

### Очистка текста от личных данных

Полный текст задачи очищается сразу после скачивания (`tools/collector/scrub.py`), поэтому в LLM,
очередь `geo-state.json`, архив `archive.sqlite` и его Excel попадает только очищенный.
Вместо вырезанного — метки: `[телефон]`, `[email]`, `[подпись]`, `[цитата]`, `[ссылка]`, `[доб.]`, `[контакт]`.

- Вырезаются блоки, а не «всё после „С уважением“»: заказ часто лежит в цитате ниже подписи, поэтому
  цитаты сохраняются, убираются только их заголовки («От: / Кому: / Тема:…», «… пишет:»).
- Имена — только в подписи, по лимиту: до 6 коротких (≤ 90 символов) строк после «С уважением /
  Best regards», до 200 символов, если подпись склеена с текстом в одну строку, и 1–3 слова с
  заглавной прямо перед телефоном. Имена в тексте заказа («Иван, привет», «согласовано с Петровым»)
  не трогаются — по форме их не отличить от названий мест («Нижний Новгород», «Золотой Колодезь»).
- Правила меняются — поднять `VERSION` в `scrub.py`: сборщик в следующий запуск один раз перечистит
  уже сохранённое (очередь, архив, Excel затронутых дней).
- Тесты на выдуманных примерах: `python tools/collector/test_scrub.py`; замер на архиве заявок
  (локально): `python tools/collector/scrub.py in/tasks_enriched_batch_size10.csv` — на 38 634 текстах
  потеряно 0,03% топонимов, телефонов и e-mail не осталось. Подробности — [issue #3](https://github.com/n-kits/gantt-report/issues/3).

### Локальный архив и «Период» на сайте

Всё, что видит сборщик, копится в `%LOCALAPPDATA%\gantt-collector\archive.sqlite` (задачи с
полными описаниями, анализ, топонимы); каждый запуск обновляет задачи окна, задачи, пропавшие
из Bitrix (удалены, ушли из фильтра) в пределах окна, из архива убираются. Когда рабочий день (с 04:00 до 04:00)
выпадает из трёхдневного окна, он выгружается в `Документы\Лента времени — архив\ГГГГ-ММ-ДД.xlsx`
(листы «Задачи» и «Топонимы»). Папка — `archive_dir` в `config.json`; выключить — `"archive": false`;
выгрузить день вручную — `python tools/collector/collect.py --export-day 2026-09-28`.

**Календарик «Период с … / Дней» в шапке** заменяет ретроспективную выгрузку: выбрали дату и
1–3 дня — страница строит ленту по архиву, «сейчас» — конец периода (04:00 следующего дня;
если он ещё не наступил — текущий момент). Стрелки ‹ › сдвигают период на день.

```
сборщик (каждый запуск) → days/ГГГГ-ММ-ДД.json в ветке data — строки дня, зашифровано тем же паролем
                          (переписывается, только если строки изменились)
                        → days/index.json — открыто: только даты и время последней сверки с Bitrix
раз в сутки (первый запуск после 04:00) → перечитать refresh_days (14) закрытых дней:
                          на сайте и в Excel — текущие статусы
```

- Статусы — текущие из Bitrix на момент сверки; строка над лентой показывает, на когда
  («статусы на 02.10 04:15»). Дни старше `refresh_days` обновляются только догрузкой.
- Догрузить прошлое (или обновить статусы за любой период) — на ПК со сборщиком:
  `python tools/collector/collect.py --backfill 2026-01-01 [2026-09-30]` (вторая дата — по умолчанию
  сегодня). Ходит в Bitrix кусками по `chunk_days` (3) суток с паузой `chunk_pause_sec`, пишет
  архив и Excel, публикует дни. Плановый запуск в это время пропускается (блокировка).
- **Горизонт пресета.** Пресет «ВСЕ КАРТЫ Р24» (`tasks_url`) не отдаёт задачи старше ~5 суток, даже
  с явным диапазоном дат — для догрузки и обновления статусов старых дней нужен пресет без
  ограничения по давности: его адрес — `history_url` в `config.json` (по умолчанию — `tasks_url`).
  Поэтому задачи, которых Bitrix за прошлые дни не вернул, из архива не удаляются (удаление — только
  в живом окне из трёх дней).
- Публикацию дней выключает `"publish_days": false`; карта и таблица топонимов в режиме
  периода не показываются.
- Тестовые данные: `python tools/collector/selftest.py` → `tests/fixtures/days/`, проверка —
  `index.html?data=tests/fixtures/live-sample.json` (пароль `test`).

### Вкладка «Аналитика»

Вторая вкладка главной (`#analytics`) — сводка по всему архиву: разделы «Поток», «Сроки», «Люди»,
«География» с общими фильтрами (период, проект, вид продукции). Данные — один файл:

```
сборщик (каждый запуск, после days/) → analytics.json в ветке data: заказы без описаний, исполнители
                          и их профили, места по координатам, анализ LLM, время сверки дней;
                          gzip до шифрования, тот же пароль; переписывается, только если данные изменились
страница → скачивает при открытии вкладки и раз в 5 минут, расшифровывает паролем живой ленты
```

- Все файлы ветки data шифруются с одной солью PBKDF2 (`kdf-salt.json` на ПК со сборщиком, своя на
  каждый пароль): браузер вычисляет ключ один раз, а не на каждый файл.
- Свежесть статусов — как у архива: последние 3 дня — каждый запуск, до 14 дней — раз в сутки;
  на вкладке — «статусы на …», в подсказке «Заказов по дням» — время сверки каждого дня.
- Профили исполнителей (картограф / дизайнер): фамилии картографов — `"cartographers"` в `config.json`
  сборщика; в репозиторий они не попадают, на сайт — только внутри зашифрованного файла.
- Выключить публикацию — `"publish_analytics": false`.
- Стенд без пароля по локальному архиву: `python tools/collector/analytics.py` → `in/analytics.html`
  (в .gitignore), открыть через локальный сервер: `http://localhost:8765/in/analytics.html`.
- Библиотеки — с cdn.jsdelivr.net и только при первом показе: d3 (графы связей), d3-sankey, Observable Plot («Штрихи»).

### Разбор страницы

`js/sources/bitrix-tasks.js` работает с таблицей `#task-list-table`: колонки — по заголовкам,
регистрация и крайний срок — из скрытых полей, «Сегодня»/«Вчера» в завершении — по
`SERVER_TIME` страницы. Этот же файл на сайте читает сохранённую страницу `.html`.
